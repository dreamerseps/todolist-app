# 도메인 정의서 - TodoListApp

**작성일:** 2026-05-12  
**버전:** 1.1

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 앱 이름 | TodoListApp |
| 목적 | 인증된 사용자가 카테고리 기반으로 개인 할일을 체계적으로 관리할 수 있는 웹 애플리케이션 |

### 해결하는 문제

- 개인별 할일을 안전하게 저장·관리할 수 있는 수단 부재
- 사용자 인증 기반으로 데이터를 분리·보호하는 할일 관리 앱 부재
- 카테고리별 분류를 통한 체계적인 할일 관리 기능 부재

---

## 2. 핵심 도메인

| 도메인 | 설명 |
|--------|------|
| 사용자 (User) | 회원가입 및 인증을 통해 앱을 사용하는 주체 |
| 할일 (Todo) | 사용자가 등록하고 관리하는 작업 단위 |
| 카테고리 (Category) | 할일을 분류하기 위한 그룹 단위. 기본 카테고리와 사용자 정의 카테고리로 구분 |

---

## 3. 도메인 모델

### 핵심 엔티티 및 속성

#### User (사용자)
| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 고유 식별자 |
| email | String | 로그인 식별자 (유일값) |
| password_hash | String | bcrypt 해시된 비밀번호 |
| name | String | 사용자 이름 |
| provider | String | 인증 제공자 (기본값: local / 2차: google, facebook) |
| provider_id | String | OAuth 제공자의 사용자 식별자 (local 인증 시 NULL) |
| created_at | DateTime | 가입일시 |
| updated_at | DateTime | 정보 수정일시 |

#### Category (카테고리)
| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 고유 식별자 |
| user_id | UUID | 소유 사용자 (기본 카테고리는 NULL) |
| name | String | 카테고리 명칭 |
| is_default | Boolean | 기본 카테고리 여부 |

#### Todo (할일)
| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 고유 식별자 |
| user_id | UUID | 소유 사용자 |
| category_id | UUID | 분류 카테고리 |
| title | String | 할일 제목 |
| description | String | 상세 설명 |
| due_date | Date | 종료 예정일 |
| is_completed | Boolean | 완료 여부 |
| created_at | DateTime | 등록일시 |
| updated_at | DateTime | 수정일시 |

### 엔티티 관계

```
User ||--o{ Todo : "등록한다"
User ||--o{ Category : "생성한다"
Category ||--o{ Todo : "분류한다"
```

- 한 명의 User는 0개 이상의 Todo를 가진다.
- 한 명의 User는 0개 이상의 사용자 정의 Category를 생성한다.
- 하나의 Category는 0개 이상의 Todo를 포함한다.

## 4. 핵심 비즈니스 규칙

| # | 규칙 |
|---|------|
| BR-01 | 모든 기능은 인증된 사용자만 사용할 수 있다. |
| BR-02 | 사용자는 자신이 등록한 할일과 카테고리만 조회·수정·삭제할 수 있다. |
| BR-03 | 기본 카테고리는 시스템이 제공하며, 모든 사용자에게 공통 적용된다. |
| BR-04 | 사용자 정의 카테고리는 해당 사용자에게만 귀속된다. |
| BR-05 | 할일 등록 시 카테고리는 필수로 지정해야 한다. |
| BR-06 | 할일 목록은 카테고리, 종료 예정일 기간, 완료 여부 기준으로 필터링할 수 있다. |
| BR-07 | 이메일은 중복 등록이 불가하다. |
| BR-08 | 할일이 1개 이상 속한 카테고리는 삭제할 수 없다. |
| BR-09 | 이메일은 가입 후 변경할 수 없다 (로그인 식별자 고정). |

## 5. 주요 유스케이스

### UC-01. 회원가입 및 로그인
1. 사용자가 이메일, 비밀번호, 이름으로 회원가입한다.
2. 이메일 중복 여부를 검증한다.
3. 가입 후 이메일·비밀번호로 로그인하여 인증 토큰을 발급받는다.

### UC-02. 개인 정보 수정
1. 인증된 사용자가 자신의 이름, 비밀번호 등 개인 정보를 수정한다.
2. 변경 사항이 저장된다.

### UC-03. 카테고리 관리
1. 인증된 사용자가 사용자 정의 카테고리를 추가한다.
2. 기존 사용자 정의 카테고리를 수정하거나 삭제한다.
3. 기본 카테고리는 수정·삭제할 수 없다.

### UC-04. 할일 등록
1. 인증된 사용자가 제목, 설명, 종료 예정일, 카테고리를 입력하여 할일을 등록한다.
2. 할일이 해당 사용자의 소유로 저장된다.

### UC-05. 할일 목록 조회 및 필터링
1. 인증된 사용자가 자신의 할일 목록을 조회한다.
2. 카테고리, 종료 예정일 기간, 완료 여부를 조합하여 필터링한다.
3. 필터 결과에 해당하는 할일 목록이 표시된다.

### UC-06. 할일 수정 및 완료 처리
1. 인증된 사용자가 등록된 할일의 내용을 수정한다.
2. 할일의 완료 여부를 변경(완료/미완료)한다.

### UC-07. 할일 삭제
1. 인증된 사용자가 자신의 할일을 삭제한다.

## 6. 용어 사전

| 용어 | 영문 | 정의 |
|------|------|------|
| 할일 | Todo | 사용자가 수행해야 할 작업 단위 |
| 카테고리 | Category | 할일을 분류하기 위한 그룹 |
| 기본 카테고리 | Default Category | 시스템이 모든 사용자에게 공통 제공하는 카테고리 |
| 사용자 정의 카테고리 | Custom Category | 사용자가 직접 생성한 카테고리 |
| 종료 예정일 | Due Date | 할일을 완료해야 하는 목표 날짜 |
| 완료 여부 | Completion Status | 할일의 완료(true) 또는 미완료(false) 상태 |
| 인증 | Authentication | 이메일·비밀번호 기반 사용자 신원 확인 |
| 인증 토큰 | Auth Token | 로그인 후 발급되는 API 접근 자격 증명 |
