## 문서 개요

이 문서는 TodoListApp의 주요 기능을 사용자 시나리오로 설명합니다. 각 시나리오는 구체적인 페르소나와 비즈니스 규칙을 기반으로 작성되었으며, 정상 흐름과 예외 흐름을 포함합니다.

### 페르소나

- **Persona A**: 김민준 (32세, 마케터) — 출근 전 할일 등록, 모바일로 완료 체크
- **Persona B**: 이수연 (46세, 팀장) — 주간 할일 일괄 등록, 미완료 필터링
- **Persona C**: 박지호 (26세, 신입 개발자) — 모바일로 빠른 등록, PC로 정리

## 시나리오

### UC-01: 회원가입 / 로그인 / 로그아웃

#### SCN-01: 신규 사용자 회원가입

**시나리오 ID**: SCN-01  
**관련 UC**: UC-01  
**페르소나**: Persona A (김민준)  

**사전 조건**
- 사용자가 TodoListApp에 접속 가능한 상태
- 회원가입 페이지가 활성화됨

**정상 흐름**
1. 사용자가 회원가입 페이지에 접속한다.
2. 이메일 주소(예: mingun.kim@company.com)를 입력한다.
3. 비밀번호(예: SecurePass123!)를 입력한다.
4. 이름(예: 김민준)을 입력한다.
5. 회원가입 버튼을 클릭한다.
6. 시스템이 입력 정보의 유효성을 검증한다.
7. 회원가입이 완료되고, 로그인 페이지로 리다이렉트된다.

**예외/대안 흐름**
- **BR-07 위반**: 이미 가입된 이메일(mingun.kim@company.com)로 회원가입 시도
  1. 사용자가 기존 이메일을 입력한다.
  2. 시스템이 "이미 가입된 이메일입니다" 오류 메시지를 표시한다.
  3. 사용자는 다른 이메일로 재시도한다.

- **입력 오류**: 비밀번호가 요구사항(8자 이상, 대소문자·숫자·특수문자 포함)을 충족하지 않음
  1. 사용자가 약한 비밀번호를 입력한다.
  2. 시스템이 "비밀번호가 요구사항을 충족하지 않습니다" 메시지를 표시한다.
  3. 사용자는 더 강력한 비밀번호를 입력한다.

**사후 조건**
- 사용자 계정이 데이터베이스에 생성됨
- 사용자가 로그인 페이지에서 로그인 가능한 상태

#### SCN-02: 기존 사용자 로그인

**시나리오 ID**: SCN-02  
**관련 UC**: UC-01  
**페르소나**: Persona B (이수연)  

**사전 조건**
- 사용자가 이미 가입한 계정이 존재 (예: suyeon.lee@company.com)
- 로그인 페이지가 활성화됨

**정상 흐름**
1. 사용자가 로그인 페이지에 접속한다.
2. 이메일 주소(suyeon.lee@company.com)를 입력한다.
3. 비밀번호를 입력한다.
4. 로그인 버튼을 클릭한다.
5. 시스템이 사용자 인증 정보를 검증한다.
6. 로그인이 성공하고 대시보드(할일 목록)로 이동한다.

**예외/대안 흐름**
- **인증 실패**: 잘못된 비밀번호 입력
  1. 사용자가 잘못된 비밀번호를 입력한다.
  2. 시스템이 "이메일 또는 비밀번호가 올바르지 않습니다" 오류를 표시한다.
  3. 사용자는 비밀번호를 다시 입력한다.

- **미등록 이메일**: 등록되지 않은 이메일로 로그인 시도
  1. 사용자가 미등록 이메일을 입력한다.
  2. 시스템이 "등록되지 않은 이메일입니다" 메시지를 표시한다.
  3. 사용자는 회원가입 페이지로 이동하거나 정확한 이메일을 입력한다.

**사후 조건**
- 사용자가 인증된 상태로 로그인됨
- 사용자의 할일 목록과 카테고리가 로드됨
- JWT(Access Token + Refresh Token)가 발급됨

#### SCN-03: 사용자 로그아웃

**시나리오 ID**: SCN-03  
**관련 UC**: UC-01  
**페르소나**: Persona C (박지호)  

**사전 조건**
- 사용자가 로그인한 상태
- 대시보드 또는 앱의 어느 페이지에나 있을 수 있음

**정상 흐름**
1. 사용자가 우측 상단 메뉴(또는 프로필 아이콘)를 클릭한다.
2. 드롭다운 메뉴에서 "로그아웃" 옵션을 선택한다.
3. 시스템이 세션을 종료한다.
4. 사용자가 로그인 페이지로 리다이렉트된다.

**예외/대안 흐름**
- 없음 (정상 흐름만 존재)

**사후 조건**
- 사용자의 세션이 종료됨
- 메모리(Zustand)의 Access Token과 Refresh Token이 모두 제거됨
- 사용자가 로그인 페이지에 위치함

### UC-02: 개인 정보 수정

#### SCN-04: 사용자 이름 변경

**시나리오 ID**: SCN-04  
**관련 UC**: UC-02  
**페르소나**: Persona A (김민준)  

**사전 조건**
- 사용자가 로그인한 상태 (BR-01)
- 개인정보 수정 페이지가 접근 가능함

**정상 흐름**
1. 사용자가 설정 또는 프로필 메뉴에서 "개인정보 수정"을 클릭한다.
2. 현재 이름(예: 김민준)이 입력 필드에 표시된다.
3. 사용자가 새로운 이름(예: 민준 김)을 입력한다.
4. "저장" 버튼을 클릭한다.
5. 시스템이 변경사항을 검증하고 데이터베이스에 반영한다.
6. 성공 메시지("개인정보가 수정되었습니다")가 표시된다.

**예외/대안 흐름**
- **빈 입력**: 이름 필드를 비운 채로 저장 시도
  1. 사용자가 이름을 삭제하고 저장을 클릭한다.
  2. 시스템이 "이름은 필수 입력 항목입니다" 오류를 표시한다.
  3. 사용자는 올바른 이름을 입력한다.

- **동일한 정보**: 현재 이름과 동일한 이름으로 수정 시도
  1. 사용자가 변경 없이 저장을 클릭한다.
  2. 시스템이 "변경된 정보가 없습니다" 메시지를 표시한다.
  3. 다른 항목을 수정하거나 페이지를 닫는다.

**사후 조건**
- 사용자의 이름이 데이터베이스에서 업데이트됨
- 사용자 프로필에 새 이름이 반영됨

#### SCN-05: 비밀번호 변경

**시나리오 ID**: SCN-05  
**관련 UC**: UC-02  
**페르소나**: Persona B (이수연)  

**사전 조건**
- 사용자가 로그인한 상태 (BR-01)
- 비밀번호 변경 페이지가 접근 가능함

**정상 흐름**
1. 사용자가 설정 메뉴에서 "비밀번호 변경"을 클릭한다.
2. 현재 비밀번호를 입력한다.
3. 새로운 비밀번호(예: NewSecure456!)를 입력한다.
4. 새로운 비밀번호를 다시 확인 입력한다.
5. "변경" 버튼을 클릭한다.
6. 시스템이 현재 비밀번호를 검증하고, 새 비밀번호의 유효성을 확인한다.
7. 비밀번호가 성공적으로 변경되고 확인 메시지가 표시된다.

**예외/대안 흐름**
- **현재 비밀번호 오류**: 잘못된 현재 비밀번호 입력
  1. 사용자가 올바르지 않은 현재 비밀번호를 입력한다.
  2. 시스템이 "현재 비밀번호가 올바르지 않습니다" 오류를 표시한다.
  3. 사용자는 정확한 비밀번호를 재입력한다.

- **비밀번호 불일치**: 새 비밀번호 입력 시 확인란과 다름
  1. 사용자가 새 비밀번호와 다른 값을 확인란에 입력한다.
  2. 시스템이 "비밀번호가 일치하지 않습니다" 메시지를 표시한다.
  3. 사용자는 올바르게 재입력한다.

- **약한 비밀번호**: 새 비밀번호가 요구사항 미충족
  1. 사용자가 "123456" 같은 약한 비밀번호를 입력한다.
  2. 시스템이 "비밀번호는 8자 이상, 대소문자·숫자·특수문자를 포함해야 합니다" 오류를 표시한다.
  3. 사용자는 더 강력한 비밀번호를 입력한다.

**사후 조건**
- 사용자의 비밀번호가 데이터베이스에서 암호화되어 저장됨
- 사용자가 새 비밀번호로 로그인 가능함

- 사용자의 이메일은 변경되지 않음
- 사용자가 이메일 변경 불가능을 인지함

### UC-03: 카테고리 관리

#### SCN-07: 기본 카테고리 확인 (수정·삭제 불가)

**시나리오 ID**: SCN-07  
**관련 UC**: UC-03  
**페르소나**: Persona A (김민준)  

**사전 조건**
- 사용자가 로그인한 상태 (BR-01)
- 사용자가 카테고리 관리 페이지에 접속함

**정상 흐름**
1. 사용자가 카테고리 관리 페이지를 열어본다.
2. 기본 카테고리 목록이 표시된다: "업무", "개인", "기타"
3. 사용자가 "업무" 카테고리를 클릭하여 상세 정보를 확인한다.
4. 편집(수정) 버튼과 삭제 버튼이 비활성화(disabled) 상태로 표시된다.
5. 시스템이 "기본 카테고리는 수정·삭제할 수 없습니다" 안내 메시지를 표시한다.

**예외/대안 흐름**
- **BR-03 위반**: 기본 카테고리 수정 시도
  1. 사용자가 개발자 도구를 이용하여 "업무" 카테고리 수정 API를 호출한다.
  2. 시스템이 요청을 거부하고 "기본 카테고리는 수정할 수 없습니다" 오류를 반환한다.
  3. 변경이 수행되지 않는다.

- **BR-03 위반**: 기본 카테고리 삭제 시도
  1. 사용자가 "기타" 카테고리의 삭제 버튼을 클릭한다.
  2. 시스템이 "기본 카테고리는 삭제할 수 없습니다" 경고 메시지를 표시한다.
  3. 삭제가 수행되지 않는다.

**사후 조건**
- 기본 카테고리는 변경되지 않음
- 사용자가 기본 카테고리의 불가변성을 인지함

#### SCN-08: 사용자 정의 카테고리 추가

**시나리오 ID**: SCN-08  
**관련 UC**: UC-03  
**페르소나**: Persona B (이수연)  

**사전 조건**
- 사용자가 로그인한 상태 (BR-01)
- 카테고리 관리 페이지가 접근 가능함

**정상 흐름**
1. 사용자가 카테고리 관리 페이지를 열어본다.
2. 기본 카테고리 하단에 "+ 카테고리 추가" 버튼이 보인다.
3. 사용자가 해당 버튼을 클릭한다.
4. 새 카테고리 추가 폼이 나타난다.
5. 사용자가 카테고리 이름(예: "마케팅")을 입력한다.
6. "저장" 버튼을 클릭한다.
7. 시스템이 입력값을 검증하고 데이터베이스에 저장한다.
8. 성공 메시지("카테고리가 추가되었습니다")가 표시되고, 새 카테고리가 목록에 추가된다.

**예외/대안 흐름**
- **중복 카테고리**: 같은 이름의 카테고리가 이미 존재
  1. 사용자가 기존 카테고리 이름(예: "업무")을 입력한다.
  2. 시스템이 "이미 존재하는 카테고리 이름입니다" 오류를 표시한다.
  3. 사용자는 다른 이름을 입력한다.

- **빈 입력**: 카테고리 이름을 입력하지 않고 저장
  1. 사용자가 이름 필드를 비운 채로 저장을 클릭한다.
  2. 시스템이 "카테고리 이름은 필수 입력 항목입니다" 오류를 표시한다.
  3. 사용자는 올바른 이름을 입력한다.

- **BR-04**: 다른 사용자의 카테고리 접근 시도
  1. 사용자 A의 세션에서 사용자 B의 카테고리 생성 API를 호출한다.
  2. 시스템이 권한 오류("접근 권한이 없습니다")를 반환한다.
  3. 카테고리가 생성되지 않는다.

**사후 조건**
- 새 카테고리가 해당 사용자의 카테고리 목록에 추가됨
- 새 카테고리는 할일 등록 시 선택 가능함
- 다른 사용자는 이 카테고리를 볼 수 없음 (BR-04)

#### SCN-09: 사용자 정의 카테고리 수정

**시나리오 ID**: SCN-09  
**관련 UC**: UC-03  
**페르소나**: Persona C (박지호)  

**사전 조건**
- 사용자가 로그인한 상태 (BR-01)
- 사용자가 "프로젝트A" 사용자 정의 카테고리를 보유
- 카테고리 관리 페이지가 접근 가능함

**정상 흐름**
1. 사용자가 카테고리 관리 페이지를 열어본다.
2. 사용자 정의 카테고리 "프로젝트A" 옆의 편집 아이콘을 클릭한다.
3. 카테고리 수정 폼이 나타나고, 현재 이름이 입력 필드에 표시된다.
4. 사용자가 새로운 이름(예: "프로젝트B")을 입력한다.
5. "저장" 버튼을 클릭한다.
6. 시스템이 변경사항을 검증하고 데이터베이스에 반영한다.
7. 성공 메시지("카테고리가 수정되었습니다")가 표시되고, 목록이 업데이트된다.

**예외/대안 흐름**
- **중복 이름**: 수정하려는 이름이 이미 존재하는 카테고리명
  1. 사용자가 "개인" (기본 카테고리 또는 기존 사용자 정의 카테고리)으로 변경을 시도한다.
  2. 시스템이 "이미 존재하는 카테고리 이름입니다" 오류를 표시한다.
  3. 사용자는 다른 이름을 입력한다.

- **동일한 이름**: 수정할 이름이 현재 이름과 동일
  1. 사용자가 변경 없이 저장을 클릭한다.
  2. 시스템이 "변경된 정보가 없습니다" 메시지를 표시한다.
  3. 다른 항목을 수정하거나 페이지를 닫는다.

**사후 조건**
- 카테고리 이름이 데이터베이스에서 업데이트됨
- 해당 카테고리의 모든 할일은 변경된 카테고리명으로 유지됨
- 사용자의 할일 목록에서 새 카테고리명으로 표시됨

#### SCN-10: 카테고리 삭제 (할일 미존재)

**관련 UC**: UC-03  
**페르소나**: Persona A (김민준)

4. 사용자가 "확인" 버튼을 클릭한다.
5. 시스템이 해당 카테고리를 데이터베이스에서 삭제한다.
6. 성공 메시지("카테고리가 삭제되었습니다")가 표시되고, 목록에서 사라진다.

  3. 삭제가 수행되지 않는다.

**사후 조건**
- 카테고리가 데이터베이스에서 완전히 삭제됨
- 사용자의 카테고리 목록에서 제거됨
- 향후 할일 등록 시 해당 카테고리를 선택할 수 없음

### UC-04: 할일 등록

#### SCN-11: 기본 정보로 할일 등록

**시나리오 ID**: SCN-11  
**관련 UC**: UC-04  
**페르소나**: Persona C (박지호)  

**사전 조건**
- 사용자가 로그인한 상태 (BR-01)
- 할일 목록 페이지 또는 할일 등록 페이지가 접근 가능함
- 사용자가 최소 하나 이상의 카테고리를 보유 (BR-03: 기본 카테고리 포함)

**정상 흐름**
1. 사용자가 "할일 추가" 또는 "+" 버튼을 클릭한다.
2. 할일 등록 폼이 나타난다.
3. 사용자가 할일 제목(예: "회의 자료 준비")을 "제목" 필드에 입력한다.
4. 사용자가 카테고리(예: "업무")를 선택한다 (BR-05: 필수).
5. "등록" 버튼을 클릭한다.
6. 시스템이 필수 정보를 검증한다.
7. 할일이 데이터베이스에 저장되고, 할일 목록에 추가된다.
8. 성공 메시지("할일이 등록되었습니다")가 표시된다.

**예외/대안 흐름**
- **BR-05 위반**: 카테고리 미선택
  1. 사용자가 제목만 입력하고 카테고리를 선택하지 않는다.
  2. 사용자가 "등록" 버튼을 클릭한다.
  3. 시스템이 "카테고리는 필수 선택 항목입니다" 오류를 표시한다.
  4. 사용자는 카테고리를 선택한 후 다시 등록한다.

- **제목 미입력**: 제목 필드가 비어있음
  1. 사용자가 제목을 입력하지 않고 등록을 시도한다.
  2. 시스템이 "제목은 필수 입력 항목입니다" 오류를 표시한다.
  3. 사용자는 제목을 입력한다.

**사후 조건**
- 할일이 데이터베이스에 저장됨 (기본값: 미완료 상태)
- 할일 목록에 즉시 표시됨
- 등록일시가 현재 시간으로 설정됨

#### SCN-14: 카테고리로 필터링

- 사용자가 여러 카테고리에 걸쳐 할일을 등록함 (예: "업무" 5개, "개인" 3개)
- 할일 목록 페이지가 접근 가능함

**정상 흐름**
1. 사용자가 할일 목록 페이지에 접속한다.
2. 페이지 상단 또는 좌측에 필터 패널이 보인다.
3. "카테고리" 필터에서 "업무"를 선택한다.
4. 할일 목록이 즉시 업데이트되어 "업무" 카테고리의 할일만 표시된다.
5. 나머지 필터(기간, 완료 여부)는 적용되지 않거나 선택 가능하다.

**예외/대안 흐름**

  1. 사용자가 "업무" 및 "개인" 체크박스를 선택한다.
  2. 시스템이 두 카테고리의 할일을 모두 표시한다 (OR 조건).
  3. 총 8개의 할일이 표시된다.

  1. 사용자가 선택된 카테고리를 다시 클릭하거나 "전체" 옵션을 선택한다.
  2. 필터가 해제되고 전체 할일이 다시 표시된다.

**사후 조건**
- 선택된 카테고리의 할일만 표시됨
- 다른 필터와 조합 가능함
- 필터 상태가 URL 또는 세션에 유지될 수 있음

4. 완료 여부 필터에서 "미완료"를 선택한다.
5. 할일 목록이 3개 필터의 교집합(AND)을 적용하여 결과를 표시한다 (예: 5개).
6. 필터 상태가 시각적으로 명시되어 표시된다 (예: "업무 + 2026-05-13~20 + 미완료").

**예외/대안 흐름**

  1. 사용자가 "필터 초기화" 또는 "전체 보기" 버튼을 클릭한다.
  2. 모든 필터가 해제되고 전체 할일이 표시된다.

- **결과 없음**: 필터 조건을 만족하는 할일이 없음
  1. 사용자가 특정 카테고리와 기간을 조합하여 필터링한다.
  2. 해당 조건의 할일이 없다.
  3. 시스템이 "조건에 맞는 할일이 없습니다" 메시지를 표시한다.
  4. 사용자는 필터를 조정할 수 있다.

**사후 조건**
- 모든 필터의 교집합을 만족하는 할일만 표시됨

### UC-06: 할일 수정 / 완료·미완료 토글

#### SCN-19: 할일 정보 수정

**시나리오 ID**: SCN-19  
**관련 UC**: UC-06  
**페르소나**: Persona A (김민준)  

**사전 조건**
- 사용자가 로그인한 상태 (BR-01, BR-02: 자신의 할일만 수정 가능)
- 사용자가 기존 할일을 보유
- 할일 목록 또는 상세 페이지가 접근 가능함

**정상 흐름**
1. 사용자가 수정하려는 할일을 클릭하거나 편집 아이콘을 클릭한다.
2. 할일 상세/수정 페이지가 열린다.
3. 현재 할일 정보(제목, 설명, 카테고리, 종료 예정일)가 입력 필드에 표시된다.
4. 사용자가 제목(예: "회의 자료 준비" → "회의 자료 준비 및 검토")을 수정한다.
5. 사용자가 종료 예정일(예: 2026-05-15 → 2026-05-17)을 변경한다.
6. "저장" 버튼을 클릭한다.
7. 시스템이 변경사항을 검증하고 데이터베이스에 반영한다.
8. 성공 메시지("할일이 수정되었습니다")가 표시되고, 할일 목록으로 돌아간다.

**예외/대안 흐름**
- **제목 삭제**: 제목을 공란으로 수정 시도
  1. 사용자가 제목을 삭제하고 저장을 클릭한다.
  2. 시스템이 "제목은 필수 입력 항목입니다" 오류를 표시한다.
  3. 사용자는 제목을 다시 입력한다.

- **카테고리 변경**: 카테고리를 다른 카테고리로 변경
  1. 사용자가 "업무"에서 "개인"으로 카테고리를 변경한다.
  2. 시스템이 변경사항을 검증하고 반영한다.
  3. 할일이 새 카테고리로 이동한다.

- **BR-02 위반**: 다른 사용자의 할일 수정 시도
  1. 사용자 A가 사용자 B의 할일 수정 API를 호출한다.
  2. 시스템이 권한 오류("이 할일을 수정할 권한이 없습니다")를 반환한다.
  3. 수정이 수행되지 않는다.

**사후 조건**
- 할일의 정보가 데이터베이스에서 업데이트됨
- 할일 목록에 변경된 정보가 반영됨
- 정렬 및 필터링이 새 정보로 재계산됨
